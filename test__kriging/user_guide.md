# Interpolation Benchmark User Guide

This document explains the directory structure and the meaning of the diagnostic outputs generated by the interpolation benchmarking harness.

## 1. Directory Structure

For every scenario defined in `scenarios.yaml`, a corresponding diagnostics folder is created:
`{ScenarioName}_diagnostics/`

Example: `S7_HighAniso_45deg_1pct_diagnostics/`

## 2. File Meanings

### `comparison.png`
The primary visual summary of the test. It contains 6 panels:
1. **Ground Truth**: The simulated "perfect" raster with red dots indicating where samples were taken.
2. **GPR Pred**: The full grid reconstructed by the **RotatedGPR** engine.
3. **Kriging Pred**: The full grid reconstructed by the **AnisotropicKriging** engine.
4. **GPR |Error|**: Absolute difference between GPR prediction and Ground Truth.
5. **GPR StdDev**: The theoretical uncertainty (standard deviation) map from GPR.
6. **Kriging StdDev**: The theoretical uncertainty map from Kriging.

### `variogram_omni.png`
Shows the **Omnidirectional Empirical Variogram**.
- **Red Circles**: The actual semivariance calculated from the sample pairs.
- **Blue Line**: The "Ground Truth" model based on the parameters used to generate the data.
- **Top Info Box**: Details on the adaptive lag selection (number of lags, lag width, max lag, and median nearest-neighbor distance).
- **Bottom Bar Chart**: Shows the number of point pairs available in each distance bin. A stable variogram usually requires >30 pairs per bin.

### `variogram_directional.png`
Displays variograms calculated along specific azimuths (0°, 45°, 90°, 135°).
- Used to verify if the engine successfully captured the **Anisotropy** (the direction where the range is longest).
- If the curves are spread apart, the field is anisotropic. If they are overlapping, it is isotropic.

### `cv_dashboard_GPR.png` / `cv_dashboard_Kriging.png`
A 3-panel report for **Spatial Cross-Validation**:
1. **Goodness of Fit**: Scatter plot of Observed vs. Predicted values. 
    - Includes **RMSE**, **MAE**, and **RMSS** (Root Mean Square Standardized).
    - **RMSS ≈ 1.0**: The engine's uncertainty estimates are perfectly calibrated.
    - **RMSS < 1.0**: The engine is too "pessimistic" (overestimating error).
    - **RMSS > 1.0**: The engine is too "optimistic" (underestimating error).
2. **Spatial Z-Score Map**: Shows where the model is struggling. Blue/Red dots indicate "surprises" where the actual value was far from the prediction relative to the predicted uncertainty.
3. **Consistency Check**: Points sorted by value. Shows if the 95% Confidence Interval (gray bars) successfully captures the black dots (observed values).

### `anisotropy_ellipse_GPR.png` / `anisotropy_ellipse_Kriging.png`
A geometric visualization of the learned spatial correlation:
- **Blue Dashed Ellipse**: The true anisotropy used in simulation.
- **Red/Salmon Ellipse**: The anisotropy parameters (angle and ratio) that the engine actually "learned" from the data.
- Helps identify if the engine correctly identified the rotation angle.

## 3. Global Summary

### `benchmark_summary.csv`
A master table located in the root `test__kriging` folder. It appends a new row for every scenario run, allowing for easy comparison of:
- **True vs. Recovered Parameters**: Angle, Ratio, Nugget.
- **Error Metrics**: RMSE, MAE.
- **Calibration**: RMSS.
- **Metadata**: Sampling density and number of points.
